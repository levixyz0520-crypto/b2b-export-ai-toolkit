# Security Policy

## Supported versions

Until the first stable release, security fixes target the latest code on `main`. No long-term support promise is made for pre-1.0 versions.

## Reporting a vulnerability

Do not open a public issue. Use GitHub's private vulnerability reporting feature if enabled. Otherwise contact the repository owner privately through the contact method on their GitHub profile, without including secrets in the first message.

Include the affected version, reproduction steps, impact, and any suggested mitigation. Allow maintainers reasonable time to investigate before disclosure. Receipt and remediation timelines depend on volunteer availability and will not be fabricated or guaranteed.

## Data and credential safety

This project does not need an API key for v0.1. Never submit real customer records, personal contact lists, authentication material, proprietary quotations, or confidential communications. Revoke exposed credentials immediately and remove sensitive data from Git history using an appropriate incident process.
